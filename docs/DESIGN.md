# 设计说明

> 这份文档是给"要在公司做二次开发的人"看的。
> 它记录**为什么这么设计**，而不只是**怎么用**。要改的时候，先看对应的决策记录。

---

## 1. 问题定义

真实事故：用户说「训练集准备好了，开始全量训推吧」，agent 沿用了 skill 里挂着的 smoke 数据集，跑了一半汇报时才发现。

表层原因是"指令没给全"。但真正的结构性问题是一句话：

> **agent 犯错时，系统里没有任何一个环节"有资格"发现它错了——因为所有校验都在问「跑通了吗」，没人在问「跑的是不是该跑的那件事」。**

所以这个项目的目标不是"限制模型"，而是在执行前插入一个**有资格说不**的环节。

## 2. 第一原则：判据必须来自程序，不来自自我报告

这是整个设计的地基，其余全部由它推出来。

**为什么**：如果你让模型"把自己要用的数据列出来"，它不会写错——它会写出一个**自洽但错**的世界（"训练集 → data/smoke/train.jsonl"，因为它认为那就是训练集）。让强模型去审这份自述，审的是一个自洽的叙事，只会盖章。

**所以有两条硬规则：**

| 规则 | 落地位置 |
|---|---|
| 契约里**只允许写路径**，行数 / mtime / 用途一律由程序实测覆盖 | `enrichRefs()` |
| "这个文件是什么用途"必须来自外部清单，不来自模型判断 | `manifest.json` |

推到一个操作规则：**凡是指代词，必须落成实体。**「训练集」「上次那个配置」出现时必须跟 path / ID；没有就机械打回。这类错误的学名是**指代消解失败**——人靠共享上下文，agent 没有"我们刚才在说那件事"。

## 3. 架构：四层，成本递增

```
                        ┌─────────────────────────┐
  tool_call (bash/write/edit) ──► ① 取证豁免 ──放行──►（只读命令、写契约）
                        │         │
                        │         ▼
                        │      ② 硬校验（纯代码，0 成本，准确率 100%）
                        │         │ 拒绝 → block + 打回理由
                        │         ▼
                        │      ③ 独立裁判（另模型，1 次 API）
                        │         │ reject/escalate → block
                        │         ▼
                        └──────► 放行
                                    │
                                    ▼
                                 ④ 留痕（tool_result 回填 result）
```

**顺序不能换**：便宜且确定的先跑。硬校验单独就能拦住本项目的目标事故（见 `test/replay`），所以它在 0 token 成本下承担了主要拦截职责；模型只处理代码判不出来的语义偏移。

### 四层各自解决什么

| 层 | 解决 | 不解决 |
|---|---|---|
| ① 取证豁免 | 死锁（要取证就得跑命令，但命令被闸拦住） | — |
| ② 硬校验 | 路径不存在 / 用途 smoke vs full / 行数不符 / 指代词未落实 / 字段缺失 | 语义层面的意图偏移 |
| ③ 独立裁判 | 指令断言与契约的矛盾、范围降级、遗漏 | 代码质量、方案优劣 |
| ④ 留痕 | 事后复盘、阶段二的训练材料 | — |

## 4. 状态机

```
             ┌─────────┐
   写契约 ──► │  draft  │
             └────┬────┘
        ┌─────────┼──────────┐
        ▼         ▼          ▼
   ② 硬校验    ③ 裁判      裁判无法判定/未配置
        │         │          │
        ▼         ▼          ▼
   rejected   pass? ──► approved   escalated
                 │ no                  │
                 └──► rejected          └── 只有人能改回 approved
```

关键点：

1. **`approved` 是唯一的放行态**，别的态一律 block。默认拒绝，不是默认放行。
2. **`escalated` 只能由人解除**（改 `state` + 填 `humanNote`）。这是系统里唯一能绕过裁判的口子——**只有人能绕**。
3. **同一契约自动判定上限 2 次**，超了强制 `escalated`。这是防死循环：模型改一版、被拒、再改、再被拒……无限循环的成本比人工贵得多。
4. 每次状态变化都落盘，所以契约文件本身 = 轨迹日志 = 复盘材料。

## 5. 证据变体：为什么做成表

裁判看什么信息，是一个 2×2 正交实验：

| 变体 | 指令/skill/契约/事实 | 工具轨迹 | 模型自述 |
|---|:---:|:---:|:---:|
| `full` | ✓ | ✓ | ✓ |
| `mask_advocacy`（默认） | ✓ | ✓ | ✗ |
| `mask_trace` | ✓ | ✗ | ✓ |
| `mask_both` | ✓ | ✗ | ✗ |

两个维度的问题是分开的：

- **遮辩护**：模型自己的解释是不是污染源（锚定效应）。锚定来自**叙事**，不来自**事实**——所以遮掉"我认为这样是合理的，因为…"，保留工具调用和文件事实。
- **遮过程**：判「指令 vs 契约」到底需不需要看它怎么干的。**如果不需要，闸就能做得极便宜**，这是能否规模化的关键。

**实现上只是一张 `KEEP` 表 + `CG_MODE` 环境变量。** 加一个变体约 20 行，切换 0 行。这是有意的：让"哪种遮法好"变成一个可以用数据回答的问题，而不是一次架构决策。

**度量**在 `test/replay/`。优先级是**漏判率**（该拒的判成 pass），不是总分——漏判是那天真正伤到人的东西，误判只是多点一次。

> 注意：现有两个用例里四列结果一样，因为硬校验先短路了。**要真正比较变体，需要加"硬校验判不出来"的用例**（用途标注正确但意图歪了、漏了评测集、范围被悄悄降级）。

## 6. 决策记录（ADR）

**ADR-1｜不用 skill 做闸**
skill 只是"把一段话加载进上下文"，**没有执行力**，而且加载后即成为规划的一部分——正好是要解决的问题。skill 只能是格式说明书，不能是强制。

**ADR-2｜裁判走独立 HTTP 端点，不走宿主 SDK**
`CG_JUDGE_BASE_URL` + OpenAI 兼容 `/chat/completions`。
理由：① 二次开发版（fork）的内部 API 一定和上游漂移，HTTP 是唯一稳定的接缝；② 天然强制"另一个模型"；③ 家里（OpenCode）和公司（omp fork）能用同一份代码。

**ADR-3｜fail-closed**
没配裁判 → `escalate`（block），不是放行。闸的价值全在"默认不放行"；一个会静默放行的闸比没有闸更糟，因为它给出"我检查过了"的错觉。逃生口是显式的 `CG_ON_NO_JUDGE=allow`。

**ADR-4｜硬校验先于模型**
确定性检查准确率 100% 且免费，不该花模型的钱和延迟。且它先跑能**短路掉大部分事故**，让模型只处理真正需要语义判断的部分。

**ADR-5｜单文件、零依赖**
公司环境装不了 npm 包、拉不动构建链是常态。单文件 `.ts` 直接拷进 `.omp/hooks/pre/` 就能跑；Node 24 / Bun 都能直接执行 TS。代价是文件较长，但**可部署性 > 代码整洁**，在这个阶段是对的取舍。

**ADR-6｜接收"指令原文可能被模型改写"这个已知缺口**
v1 不做指令 hash 绑定。理由：绑定需要拿到当前会话的用户原话，这在 fork 里未必有稳定 API；而这行的成本是**人扫一眼 `instruction` 字段（3 秒）**。等确认了 fork 的 API 再补。

## 7. 二次开发指南（公司 fork）

### 7.1 先验证三个兼容点

| 点 | 怎么验 | 不兼容时 |
|---|---|---|
| `ExtensionAPI` 存在且能 `pi.on("tool_call")` | `omp --hook ./contract-gate.ts` 看是否加载 | fork 可能只保留了 legacy `HookAPI`（`pi.on` 同名，但返回类型/字段不同） |
| `tool_call` 返回值支持 `{block, reason}` | 跑 `python x.py` 应被拦 | 退化为抛异常 / 或用 `additionalContext` 提示 |
| `event.input` 的字段名 | 打印 `Object.keys(event.input)` | `targetPath()` 已兜 `path`/`file_path`/`filePath`/`file` |

### 7.2 适配层在哪

改代码时只需要动这三处，其余逻辑与宿主无关：

1. `pi.on("tool_call", ...)` 的注册方式（第 7 节末尾）
2. `targetPath()` —— 工具入参的路径字段名
3. `ctx.cwd` —— 工作目录来源（已有 `process.cwd()` 兜底）

### 7.3 如果 fork 没有 hooks

两条退路，按代价排序：

1. **包装成 CLI**：`omp` 外面套一层脚本，在执行前后注入检查。缺点：拿不到工具级粒度。
2. **把闸下沉到训推脚本入口**：`run_train.sh` 启动前读 `current.json`，校验不过就退出。**这不 agent，但 100% 有效**，而且对"训练/推理"这类重操作其实更合适——真正需要保护的就是那一个入口。

### 7.4 换成你们的数据源

`manifest.json` 只是"数据集 → 路径 + 用途 + 行数"的一张表。如果公司有数据注册表/实验平台 API，把 `loadManifest()` 换成一次 HTTP 拉取即可，后面全部逻辑不变。

### 7.5 裁判换成内网模型

只要提供 OpenAI 兼容的 `/chat/completions`，填三个环境变量即可。**强烈建议换族**（和规划模型不同厂商/不同家族）——同族模型的自我偏袒是结构性的，不是靠提示词能消掉的。

## 8. 明确不解决的问题

写下来是为了防止它长成一个什么都管的东西：

- **不判断方案优劣**。裁判只问"这是不是用户要的那件事"，不问"这是不是最好的做法"。
- **不替代测试**。它是执行前的闸，不是执行后的验证。
- **不做跨会话记忆**。契约是单次任务的。跨任务的知识沉淀是阶段二的事（`humanNote` 的累积）。
- **不防止人自己说错**。如果你真的说错了，闸会放行一个错误的任务——它保护的是"你说的和你以为的一致"，不是"你说的对"。

## 9. 演进路线

| 版本 | 内容 |
|---|---|
| v0.1（当前） | 硬校验 + 独立裁判 + 证据变体 + 回放集 |
| v0.2 | 指令 hash 绑定；契约改用「提交工具」而非写文件；`diffFromLastRun` 自动生成（对比上次契约） |
| v0.3 | `humanNote` 回流：打回时强制人写一句，累积成"个人盲区地图" |
| 阶段二 | 复盘仪式：从模仿 → 批判 → 掌握。契约本身就是器材——**它把"读 agent"的成本压回了人类尺度** |
